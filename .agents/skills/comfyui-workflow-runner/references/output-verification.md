# 产出校验配方

运行成功 ≠ 产出正确。每次都要探测文件并**真的看一眼**。

## 1. 探测（区分 temp 预览与已保存产出）

```bash
ffmpeg -hide_banner -i <file> 2>&1 | grep -E 'Duration|Stream #'
```

关注：时长、分辨率、帧率、**是否存在音频流**（FallingTS 的预览节点与部分工作流不带音轨；
用户可能明确表示不需要音频，此时不要当成缺陷）。

定位最近任务的产出：

```bash
python scripts/list-recent-outputs.py   # /history?max_items=N 的输出文件映射
```

**注意**：`PreviewVideo` / `PreviewImageSave` 默认只写 `ComfyUI/temp/`（点「保存」才写 output），
所以 media 目录里找不到不代表没生成。
但 `AutoSaveImage`（`0035_场景截帧` 的十个图片保存节点、`0050_视频拆帧` 的三个）**执行到即写 output**，
无头提交时要自己在 `extra_pnginfo` 里带工作流名（顶层 `workflow_name`），否则产物退回 output 根目录。

## 2. 抽帧拼板

```bash
# 1 秒 1 帧，12 秒 → 4x3
ffmpeg -y -i in.mp4 -vf "fps=1,scale=480:-1,tile=4x3" -frames:v 1 grid.png
# 均匀 N 帧（如 8 帧：fps=8/时长）
ffmpeg -y -i in.mp4 -vf "fps=2/3,scale=640:-1,tile=4x2" -frames:v 1 grid8.png
```

然后**读图**判断内容、构图演进、物件是否漂移或凭空增减。

## 3. 运动一致性（定量）

### 3.1 整体镜头节奏（pblack）

```bash
ffmpeg -hide_banner -i in.mp4 \
  -vf "fps=2,scale=160:90,tblend=all_mode=difference,blackframe=amount=0:threshold=10" \
  -f null - 2>&1 | grep pblack
```

`pblack` = 差异后接近纯黑的像素百分比，**越大表示运动越小**。

判读：匀速镜头应近似**恒定**；出现 80+ 的尖峰即停顿/吸附，出现 <30 的谷值即猛冲/跳变。
把整条曲线打印成柱状，一眼能看出节奏是否均匀。

### 3.2 ⚠️ pblack 看不出「被摄体有没有在动」

H3 出片颗粒极重。实测 `0044_参考视频`（全画幅，`threshold=8`）：**机位完全静止**的雨窗段
`pblack` 在 **86~98** 波动，而「双手完全冻结」的那一秒是 **89~99** —— **两者重叠，无法区分**。
所以 pblack 只适合判断"镜头整体节奏"（匀速 / 停顿 / 猛冲），不能用来回答「手 / 脸 / 物件到底动没动」，
也不能用它比较两次渲染里主体的动作幅度。

要判断某个部位的运动量，用 `scripts/motion-profile.py`：先高斯模糊抹掉颗粒，再取相邻帧差分的
**中位数**（对切镜那一帧的跳变稳健），并用 `--crop` 把 ROI 收到目标部位。

```bash
python scripts/motion-profile.py in.mp4                                  # 全画幅
python scripts/motion-profile.py in.mp4 --crop 640:300:60:140            # 手部 ROI，crop = w:h:x:y
python scripts/motion-profile.py in.mp4 --crop 640:300:60:140 --json     # 脚本化对比
```

判读口径（实测样本 = 同一个手部特写改造前后，同一 ROI）：

| 状态 | ROI 差分中位数 |
|---|---|
| 被摄体冻结（只剩颗粒与雨） | 0.1 ~ 0.7 |
| 有持续动作 | 2 ~ 4.5 |

单帧 `max > 30` 基本就是一次切镜。**比较时必须同一 ROI、同一 `--scale`**，否则不可比。
`--fps` 默认 24（H3 固定帧率），改帧率的工作流要一并改它。

### 3.3 ⚠️ 跨 take 比较：先确认窗口没夹进切点，再除以本 take 的静态控制区

H3 每次重roll 的雨量/颗粒/切点都在变，**直接比绝对值会得到相反结论**。第六轮踩坑实录：取 5.60–6.95s
当"机位静止窗"，新片全幅中位 0.125→0.250、连本应静止的窗区都从 0.188 涨到 0.438 → 误判成"手部相对
运动下降"；逐帧剖面才发现新片 **6.40–6.61s 已经在切镜**（旧片切在 6.76s），切换瞬间把整幅差值抬起来了。

三步口径（`scripts/motion-frame-profile.py` 逐帧打印全幅/各 ROI 帧间差，并把静态控制区一起打出来）：

```bash
python scripts/motion-frame-profile.py old.mp4 new.mp4 --t0 5.65 --t1 6.35 --fps 12 \
    --roi 手:330,310,490,410 --roi 臂背:150,240,320,340 --control 右上角:740,0,830,130
```

1. **先定位切点**：对 ≤2s 的候选窗逐帧看全幅差，单帧飙到几十以上就是切镜；取**两片都还没切、
   全幅差已落到地板**的区间（本轮最终用 5.65–6.35s）。
2. **设一个静态控制区**：画面里确定不动的结构（本轮 = 右上角夜空，地板 0.14–0.16），它必须两片持平，
   否则说明相机动了/光照变了，该窗口作废。
3. **报"区域 ÷ 静态控制区"**，而不是裸值：本轮手臂/后背区 **2.62x → 4.94x**（手/键盘 4.37x → 6.08x），
   同时雨/窗区只 +15% —— 这样才能把"这块真的更动了"与"整幅都更躁了"分开。

## 4. 镜头运动类型判别

从抽帧图上判断是**原地旋转**还是**平移**：

- 原地旋转（pan / turn in place）：中心物体保持在画面中央附近，四周背景依次滑入滑出
- 平移（tracking）：被摄主体从画面中央**移向一侧**，像布景横向掠过

提示词里误用「环绕 / orbit」会导致模型做出平移 —— 该词在影视术语中指"机位绕主体转圈"，
而"以场景中央为轴旋转"应写 **固定机位 + 原地水平转动**。

## 5. 音频（仅在需要时）

```bash
ffmpeg -hide_banner -i in.mp4 -af astats=metadata=1:reset=1 -f null - 2>&1 | grep -E 'Peak|RMS'
```

- 峰值贴 0 dBFS 且长时间持平 → 削波/爆音
- H3 原生音轨为 32 kHz 立体声；采样率异常说明链路被改动过

## 6. 缓存陷阱

执行缓存会让**逐字节相同**的工作流秒回结果。做 A/B 时务必改 seed 或提示词，
否则会把"5 秒的缓存命中"当成真实渲染耗时（真实 H3 480p 4 步约 140-190 秒）。
