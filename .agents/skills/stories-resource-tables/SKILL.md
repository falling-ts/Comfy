# 故事库资源表与提示词通用规范（总纲）

> 本技能是资源表的**总纲**：尺寸规范、分段规则与 H3 语言规范对**所有**资源类型都适用，场景与视频类技能会引用它。各类型条目分散在技能 `stories-scene-video`、`stories-video-prompts`、`stories-audio-resources` 中。

## 画面术语定义（面/侧/边/视/词）

五种术语全文档严格区分，严禁混用：

1. **面**：代表三维空间拍摄的具体画面（场景某一朝向的画面），共**九方位**：前面（正面）、前右、右面、右后、后面、后左、左面、左前、全图（四个正方向 + 四个斜方向 + 全景俯瞰）；场景类列名与提示词内容中的「面」一律指被描述的画面朝向
2. **侧**：代表摄像机在哪侧，**永远与面相对**：左侧相机拍摄的是右面，右侧相机拍摄的是左面，后侧相机拍摄的是前面，前侧相机拍摄的是后面；斜向同理——左前侧相机拍摄的是右后面，右后侧相机拍摄的是左前面，后左侧相机拍摄的是前右面，前右侧相机拍摄的是后左面；上下同理（上侧相机拍摄的是下面，下侧相机拍摄的是上面）
3. **边**：代表一个场景画面九宫格的哪一边（方位格），例如 左边在中间的左边，右上在中间的右边的上边
4. **视**：与场景无关，只与万物有关；万物类**物品/生物**画面统一采用三视图（2026-10-07 起，横向并排三个视角，左边是正面、中间是侧面、右边是后面）；**万物类人物**（2026-10-07 改版）改为**「正脸特写 + 衣服参考」左右双区并排**版式，详见「万物建模 提示词提取规范」。两种版式都不是九宫格
5. **词**：仅分 正词 与 负词；资源表提示词列后缀一律写 -正词 / -负词，词名中不得出现「面」字（避免与画面的面冲突）；提示词正文中出现的「面」指画面的面（如旋镜提示词「右面是…」）

## 资源表

所有资源文件均为表格 md 文件，全文件仅由一个表格构成，严禁出现任何标题

### 图片提示词书写顺序规范

万物建模、万物变化、场景首帧、场景拉镜、场景推镜 的提示词，除遵循各自类型的专属要求外，还必须严格按照以下顺序书写：

1. **整体图片品质**：描述整图画质、清晰度、精细度、光影氛围、环境背景等整体视觉表现
2. **图片元素万物**：列出画面中出现的所有元素与万物（人物、器物、场景物体、生物、道具、自然景物等）
3. **图片风格要求**：写明整体艺术风格。**本故事库所有生图类资源（万物建模、万物变化、场景首帧/拉镜/推镜/旋镜）默认统一采用「写实三维CG风格」**：次世代三维渲染质感，立体体积感明确，真实材质与皮肤纹理（保留毛孔与细微纹理，不做平涂磨皮），影棚级立体布光与自然明暗过渡。⚠️ **2026-09-22 起整体改写实三维CG**（旧规范为「国漫CG风格」且严禁"写实"字样，已废止）：实测国漫CG 正词叠加负词里的 `写实摄影`/`实拍照片` 会把画面压成 2D 动漫平涂脸，故**负词里严禁再出现 `写实摄影`/`实拍照片`**，要压制的是 `二维动漫`/`二次元平涂`/`卡通渲染`/`赛璐璐上色`/`塑料感皮肤`/`过度磨皮`。注意「不向纯白背景投射阴影」≠「主体没有立体光影」，主体自身必须有体积与明暗过渡

三段顺序不可颠倒，缺失任一段视为不合格。

#### 提示词内容分段规则（通用，两类生图提示词共同遵守）

- **段分隔符统一**：提示词的所有分段点一律用 `<br>` 分隔（每个分段点一个 `<br>`，置于段末），段内属性用全角逗号 `，` 分隔，全文不使用句号；严禁使用换行符（真实回车 / 换行字符）或 `
`（反斜杠 n 两字符）作为分段符——md 表格单元格内的换行会被解析为新行从而断开表格，只有 `<br>` 能在单元格内安全分段；冒号仅用于点名词句（如万物类的 `主体：`），同一条目内要么全用要么全不用，保持一致。⚠️ **注意与 Qwen-Image 2.1 官方规范的冲突**：官方要求送进模型的提示词是**单段连续文本、禁任何换行**（[system_prompt_edit.txt](refs/Qwen-Image-2.1/prompt_rewrite/prompts/system_prompt_edit.txt) L186）。两者不矛盾但需两步走——**表内保留 `<br>` 以保表格结构，`<br>` 在送模型前合成单段**；现状是带着 `<br>` 直接送模型，属已知偏差。详见技能 `qwen-image-2-1-prompting`
- **一段一职责**：每段只写一类信息（整图品质 / 一个显示区域 / 一个方位格 / 风格），不跨段混写
- **段头点名词**：每段以点名词开头（如 `主体：`、`左上…`、`右面是`、`整体是…`、`写实三维CG风格`），点名词即段边界
- **一个元素只归一段**：不得在不同段重复堆叠同一元素
- **风格词只在最后一段**出现（`写实三维CG风格，…` 收尾），严禁散入品质段与区域段
- **`整体是…` 总结段全文仅一处**，紧跟区域段之后
- **段序固定**，不可颠倒，缺段视为不合格

两类提示词的分段维度不同，各自按以下规则执行：

#### 万物类分段规范（按三视图分段；人物行按双区版式分段）

万物建模、万物变化 的画面**按对象类型分两套版式**（2026-10-07 改版）：

- **物品/生物**：**三视图画面**（横向并排正面/侧面/后面三个视角，左正、中侧、右后），**不使用九宫格**
- **人物**：**「正脸特写 + 衣服参考」左右双区并排**画面（详见下）

两套都**不使用九宫格**。段序：

1. **品质段**：画质描述 + 纯白背景硬句（#FFFFFF，无环境、无场景、**不向背景投射阴影**；「不投影到背景」不等于「主体没有立体光影」，主体自身必须写明体积与明暗过渡，见各自类型规范）
2. **布局声明段**：点明画面构成与取景（物品三视图：`物品三视图并排展示，左边是正面、中间是侧面、右边是后面，三个视角为同一件物品、造型尺寸完全一致、均完整入画`；**人物双区**：`画面按短边高度划出一个边长与画布短边完全相等的正方形区域靠边放置，…`，见「万物建模 人物双区版式」一节）
3. **主体段**：`主体：` 开头，**逐视角/逐区域分段**写各区域各自可见的形态特征（外形轮廓、结构组成、材质质感、颜色配色、纹样装饰、配件部件）；**与各区域无关的共同特征**（材质、配色、风格等）只写一次、不按区域重复
4. **总结段**：`整体是…`（全文仅一次）
5. **风格段**：`写实三维CG风格，…` 收尾

点名词体系：**主体**（画面各区域的共同主体）+ **视/区域**。`主体：` 只与万物有关，**严禁出现在场景类提示词中**；万物类物品/生物**必须写出三视字样**（`三视图`，生物写 `全身三视图`、物品写 `物品三视图`）与三个视的方位（`正面`/`侧面`/`后面`），但**严禁使用特写分区**（`左边特写`）与九宫格方位格（`左上`/`中间格`等）；`正面/侧面/后面` 三个视与场景类的九方位面（`前右`/`右面`/`后面`）是**不同体系**，万物类只用前者。**人物双区**不用 `三视图` 字样，改用 `正脸特写` 与 `正面无头全身站立`，并以 `左边`/`右边` 指示方位（方位词只写在提示词里，**绝不出现在画面里**）。
万物变化段序：`以图1为底，保持原构图不变` 起头 → 主体修改段（`主体：` 开头，写改后的新外观）→ 风格段。

#### 场景类分段规范（按九宫格方位格分段）

场景首帧、场景拉镜、场景推镜、场景旋镜 的画面按**九宫格方位格**分段（见「场景图片生成 九宫格画面描述要求」）。段序：

1. **品质段**：画质 + 光影氛围描述（场景自带环境，无纯白背景要求）
2. **方位格段**：按固定顺序逐格一段——16:9 横版按 `左上…` → `左边…` → `左下…` → `上边…` → `中间…` → `下边…` → `右上…` → `右边…` → `右下…`；9:16 竖版按 `上左…` → `上边…` → `上右…` → `左边…` → `中间…` → `右边…` → `下左…` → `下边…` → `下右…`；每格段以该格方位词（边词）开头，无内容的格可略过
3. **风格段**：`写实三维CG风格，…` 收尾

点名词体系：**边词**（九宫格方位格），与万物类的 `主体：` 点名词互斥——场景类提示词中**严禁出现万物类的 `主体：` 点名词、三视图与特写分区**（`三视图`、`全身三视图`、`物品三视图`、`左边特写`）。⚠️ 场景类**允许**用 `正面`/`侧面`/`后面` 等方位词（它们属九方位面体系），但**不得**写成三视图并排结构。
特例：

**万物建模、万物变化统一用 832×480**（横屏，固定档）——物品三视图与人物双区版式都要把多个区域并排放下，画面必须**横向**；统一按 **832×480（26:15，≈0.40MP）** 一档，不再按对象形态分档：
- **场景推镜**：单帧非九宫格，不划分方位格段，仅用区域方位词描述画面内各区域的内容分布

### 视频类尺寸规范（MiniMax H3）

视频类资源（文生场景、首帧场景、文生视频、首帧视频、首尾视频、关键帧视频、参考视频）的宽度/高度按 MiniMax H3 官方 canvas 规则填写：

- H3 固定 **24fps**（模型架构常量：表内**不设「视频帧率」列**，工作流的帧数换算一律写死 ×24，输出容器帧率亦恒为 24；要变速/补帧另用 `FallingTSFrameRateConvert` 节点）；视频秒数按需求填 5~15 秒（官方训练域）
- canvas 硬规则：**短边 ≤ 768**、**面积 ≤ 768×1344（≈1.03MP）**、每轴为 **32 的倍数**；宽度/高度直接决定生成尺寸，超限不会被自动纠正
- 默认统一 16:9 = **832×480**（480p 低显存档，0.4MP，官方原生工作流默认，适配 8G 显卡）
- 显存充足（16G+）可升档 16:9 = **1344×768**（768p 官方主推档，与 turbo 4 步 LoRA 训练域一致）
- 其余比例合法桶：21:9 = 1536×672、3:2 = 1152×768、4:3 = 1024×768、1:1 = 768×768、3:4 = 768×1024、2:3 = 768×1152、9:16 = 768×1344、9:21 = 672×1536
- 低显存/加速档 9:16 = **480×832**
- **严禁使用 1664×928 等生图桶值**：面积 1.54MP 超出 H3 上限约 50%，属分布外，易质量崩坏；2K 需另行二采放大（SeedVR2 / RTX VSR），不在宽度/高度列表达

### H3 提示词语言规范（视频类资源通用）

> **2026-09-25 用户决定：提示词正文改中文，H3 关键标识保持英文。** 下表是唯一语言口径。正文（画面、运镜、光影、动作、声音、剧情的描述句）写中文，便于作者读写与维护；凡是**模型要照抄的骨架**——字段名、`<Picture N>`/`<Subject N>` 一类标签、retention 枚举、方括号任务前缀、`[Shot N]` 与紧邻时间戳、官方对齐指令整句——一律保持英文。`stories\七纹刻印\` 下 9 个含提示词的资源表已按此口径改写完毕，对应 9 个工作流的 mdtable 快照同步刷新。

**写进资源表的提示词正文一律中文**，只有对白/歌词与画面内实际可见的文字保留原语言；**骨架与镜头语言术语保持英文**。

为什么上一版写的是英文（现降级为**已知代价**，不推翻）：H3 官方提示词技能（`h3-prompt-writing`）与官方模板（`templates\视频\api_minimax_h3_max_r2v.json` 等）的示例 prompt 全为英文；官方 HF 仓库讨论 #32 中经官方人员编辑的答复为「除需要生成的文字和对白内容，其他都要用英文描述」；官方模型卡载明 H3-Encoder 取 **Qwen3-VL-32B 第 50 层隐状态**送进 H3-Omni-Transformer，生成主干是在英文条件上训练的，故中文条件落在分布外。本机 `qwen3vl_32b_minimax_h3_nvfp4_awq` 是 **4-bit** 量化编码器，多语言基准实测长提示词的词义错乱率为**英文 1.8 / 100 词、中文 3.1 / 100 词**（中文额外损失约 1.7 倍）——长提示词用英文可同时规避「条件分布外」与「量化损失」两笔代价。这些代价**不因改用中文而消失**，只转为可接受成本；实测数字与唯一的有效回退杠杆见本节末「已知代价」。

| 内容 | 填写语言 |

#### 万物建模 · 人物双区版式（2026-10-07 新规，取代人物三视图）

**适用范围**：`0011_万物建模.md` 与 `0012_万物变化.md` 里**所有 ID 是人物的行**（生物/物品行仍走三视图）。

**几何口径（硬约束，先算尺寸再写提示词）**：

- **短边 = 正脸特写区的边长**。取画布**短边**长度 S，在**长边**方向上划出一个 **S×S 的正方形**（1:1 靠边），专门用来生成**人物正脸特写**
- **长边剩下的空间（L−S）×S** 用来生成**这一身衣服的平铺参考图**（孤立衣物，不穿在任何人身上）
- **832×480（默认档）** → S=480：正脸特写区 **480×480**、衣服参考区 **352×480**
- **1664×960** → S=960：正脸特写区 **960×960**、衣服参考区 **704×960**
- 两区**紧贴画面上下边**、铺满整个短边高度，**之间不额外留白边、不加边框/相框、不加箭头与任何文字标注**
- ⚠️ **不要把像素尺寸写进提示词**（Qwen-Image 2.1 规范：比例与分辨率走宽度/高度字段）。提示词里只写**相对关系**：`左边是一块边长与画面高度相等的正方形区域…`

**两个区域的画面要求**：

- **左边 · 正脸特写区（S×S 正方形）**：**正面脸部特写**——人物头部居于该区正中央、正面朝向镜头、双眼平视前方，头部连同**肩部以上**完整入画，四周留干净纯白空白；五官结构完整清晰、左右对称、皮肤保留毛孔与细微纹理（不磨皮不美颜）；**该区内画面里不出现身体、躯干、四肢、第二个脸**
- **右边 · 衣服参考区（(L−S)×S）**：只呈现这个人**要穿的那一身衣服本身**——平铺、正面展示、完整入画、互不遮挡、各自居中并在上下方向上自然错开；衣身舒展摊平、领口/袖口/下摆自然摊开、左右对称，边缘有自然褶皱与垂坠，织物纹理清晰。⚠️ **绝不写「无头」「砍头」「斩首」「断头」** —— 那类措辞容易被读成恐怖画面，改写为「**没有任何人物穿着的孤立衣物**」。**该区内画面里不出现人、脸、头、脖子、躯干、手臂、手指、腿、脚、鞋子、衣架、模特、假人、背景场景与任何文字标注**
- **同一人**：两区是**同一个人的脸与同一身衣服**——脸的气质、发型与衣服的款式配色互相呼应
- **纯白背景**：两区共用同一片纯白背景，各自不向背景投射阴影

**⚠️ reference leakage 铁律（必读）**：方位词（`左边`/`右边`/`正脸特写`/`衣服参考`）**只写在提示词里，绝不出现在画面里**；提示词**不能描述这张参考图自身的分格结构**（否则两块版式与那条黑色实线会被画进视频画面）。这张图的正向消费方是 `0013_首图建模` / `0014_参考建模`，两者的提示词都必须显式否定分栏线与黑色实线。

**正词段序（人物行，7 段，段间 `<br>`，绝不用真实换行）**：

1. **品质段**：画质描述 + 纯白背景硬句（#FFFFFF、无环境、无场景、**不向背景投射阴影**；主体自身仍须有体积与明暗过渡）
2. **布局声明段**：写明左右双区几何（`画面按短边高度划出一个边长与画面高度相等的正方形区域靠左放置，…`）
3. **`人物设定：`** 段：年龄、相貌、发型、肤色、体型、身高体态等**跨两区共通**的特征，只写一次（衣服的款式配色只写在「衣服参考」段里，不要在这里重复）

**负词必须跟着版式反转（最关键的一步）**：版式一改，负词里上一版的压制项常常变成反效果。人物双区版式的负词至少要含：

- **数量**：多个人物, 多张脸, 重复的人物, 两个不同人物

**尚待用户拍板的取舍（不要自行决定，问过再说）**：

- **为什么右区是「衣服」而不是「无头全身」**（2026-10-07 已拍板）：无头全身丢了锚点且「无头」措辞易被读成砍头/恐怖；改用**孤立衣物**后，右区只承担**布料与款式**的锁定，脸部锚点完全由左区承担，语义更干净也让视频侧的 reference leakage 更好否定
- **正脸特写区的分辨率**：832×480 下该区仅 480×480（约 0.23MP），五官细节偏紧；若人脸辨识度不够，建议**这一行单独升到 1664×960**（脸 960×960）
- **全部对象（人物、生物、物品，不分形态）** → **832×480**（固定横屏档，见「生图类尺寸规范」）
提示词中必须逐条写出**三个视角各自**要表现的外观特征（外形轮廓、结构组成、材质质感、颜色配色、纹样装饰、配件部件）；材质、配色、风格等**跨视角共通的特征只写一次**。**必须写出三视字样**（人物写 `全身三视图`、物品写 `物品三视图`）与三个视的方位（`正面`/`侧面`/`后面`）；**严禁使用特写分区**（`左边特写`）与九宫格方位格。

**三视图内部规则**（三视并排的硬约束）：

- **同主体同规格**：三个视角的**身高/身高比例、体宽、配色、材质、配件完全相同**，只改朝向；侧面与后面不得出现与正面矛盾的细节（如正面无背包、后面却背了背包）
- **取景统一**：三个视角**取景高度与留白一致**——人物三个视角**都从头到脚完整入画**、三者头顶齐平、脚下齐平；物品三个视角**都完整入画**、视平线一致
- **纯白背景**：三个视角都悬浮在**同一片纯白背景**上，各自不向背景投射阴影
- **三等分布局**：三个视角横向**大致三等分**排列、间距均匀、各自居中，不重叠、不切边
- **无标注**：**不要**在视角之间加箭头、标签、中文/英文标注或分隔线（`正面`/`侧面`/`后面` 等文字**不出现在画面里**），也不要把三视做成拼贴相框

**按对象类型区分取景与版式**：

- **物品**：**物品三视图**，左正面、中侧面、右后面，三者造型尺寸完全一致、均完整入画；832×480
- **生物/怪物**：**全身三视图**，左正中侧右后，完整入画；832×480
- **人物**：**双区版式**（正脸特写 + 衣服参考），见上节「人物双区版式」；832×480

### 场景图片生成 九宫格画面描述要求（场景首帧 / 场景拉镜 / 场景推镜 / 场景旋镜 通用）

场景类图片生成的提示词，必须把画面按**横向、纵向各三等分**划分为**九宫格**，并逐格点名每格内出现的元素与布局（场景方位、物件、灯光、细节），使画面各区域有明确交代、不随场。

描述顺序按画面宽高比分为 **16:9** 与 **9:16** 两种，按生图的宽度/高度选用对应顺序：

**16:9（横版）**：按 **左边 → 中间 → 右边** 描述。
- 左边：按 **左上 → 左边 → 左下** 描述；
- 中间：按 **上边 → 中间 → 下边** 描述；
- 右边：按 **右上 → 右边 → 右下** 描述。

**9:16（竖版）**：按 **上边 → 中间 → 下边** 描述。
- 上边：按 **上左 → 上边 → 上右** 描述；
- 中间：按 **左边 → 中间 → 右边** 描述；
- 下边：按 **下左 → 下边 → 下右** 描述。

每格用方位词开头点名（如"中间是…""左上…"），说明该处放的物件或留空；没有内容的格可略过，但任一元素只归入其所处的那一格，不得在不同格重复堆叠。

九宫格与场景本身的空间布局（前后左右、物件相互位置关系，见技能 `stories-scene-video` 的「场景类公共要求」）要互相印证统一：中间格通常为核心主体/主光区，四边交代墙面/地平/边缘，四角补足角部朝向的底景与照明。

## 表格 md 文件规范说明

所有表格 md 文件的第一列永远是 ID

后续字段完全按照 标题(类型) 定义

(类型) 不填写默认是 (STRING)

(类型) 包含如下内容和说明:

- (IMAGE)/(VIDEO)/(AUDIO)/(MASK)/(STRING)/(INT)/(FLOAT)/(BOOLEAN)：对应 ComfyUI 同名输出类型
- (TEXT)：对应 ComfyUI 的 STRING 输出类型，但自定义节点渲染为多行文本框

实际使用情况（扫描 `stories/` 下全部含表格 md 文件）：显式声明过的只有 `TEXT`、`IMAGE`、`INT`、`VIDEO`、`AUDIO`、`FLOAT`、`MASK` 七种；`STRING` 从未显式书写（各资源表的 ID 列等一律靠省略默认）；`BOOLEAN` 已登记但尚无一处使用。

各类型的字段定义（ID + 各字段(类型)）见对应类型的技能（`stories-resource-tables` 的图片类、`stories-scene-video` 的场景类、`stories-video-prompts` 的视频类、`stories-audio-resources` 的音频类）；ID 命名规则见 `stories/AGENTS.md` 的「资源 ID 规则」。

### 全图方位

**全图**是第九个方位，代表从场景**正上方垂直向下俯瞰**的全景画面（顶视/Bird's Eye），是八面水平方位之外的垂直维度补充。

- **含义**：全图不是某一朝向的画面，而是俯瞰整个场景的鸟瞰平面图——能看到场景中所有物件、地面、边界与空间关系的完整布局
- **用途**：场景类资源描述场景空间时，除八面水平方位外，还应提供全图方位的整体俯瞰描述，使模型从二维平面理解整个场景的空间结构与物件分布
- **描述要求**：全图方位的描述按俯视平面图的方位词逐区域点名（如「上方是…」「下方是…」「左侧是…」「右侧是…」「中央是…」），与八面水平方位描述交叉印证
- **与其他方位的关系**：全图方位是八面水平方位的上层概览——八面描述的是"站在某个方向往另一个方向看"，全图描述的是"从天上看下来"；两者互补而非替代

### 建模链（0013 首图建模 / 0014 参考建模 / 0015 建模截帧）
