# MiniMax H3 人物身份遵循诊断：为什么场景完美、人物只有 0.5

> 日期：2026-10-07
> 对象：`workflows\0044_参考视频.json` + `stories\七纹刻印\0044_参考视频.md`
> 问题：场景遵从近乎完美，但人物面部相似度只有 0.5 左右；传的是 1088×1920 高清参考图、`ref_image_size=max`，为什么仍然很差
> 依据：口径全部直接读源码并按公式复算（复跑方法见 §10），像素测量取自实际参考图
> 相关：`docs/MiniMax-H3-参考图尺寸与match-max口径-2026-10-02.md`（match/max 精确口径与代价）、`docs/MiniMax-H3-参考保真度调研-2026-09-18.md`（保真度上限）、`docs/AI漫剧-人物参考图调研-2026-09-24.md`（人物参考图实测）

## 0. 结论摘要

1. **不需要像素尺寸一致，需要的是「宽高比」一致。** H3 的 2D RoPE 是面积归一化（`_axis_from_sqrt_area`），参考图与目标帧各占归一化画布上的一个矩形、逐点对齐。宽高比一致 ⇒ 两者几乎逐像素重合；不一致 ⇒ 参考图整体错位，**被裁掉的部分恰好可能是人物的头**。
2. **本工作流人物遵从差的直接原因是宽高比失配 3.06×**：参考图 1088×1920（0.567）vs 生成画布 832×480（1.733）。人物立绘的头在原图顶部 y≈0.03，映射到归一化坐标 y=**−0.127**，而目标画面从 **y=0.120** 才开始 ⇒ **整颗头落在画面之外**。
3. **同一机制完美解释了「场景好」**：两张场景参考图是 832×480（ratio 1.733），与生成画布**完全一致**，归一化画布重叠 **100%**，空间布局可 1:1 迁移。人物图只有 **57%** 重叠。
4. **这就是为什么调分辨率 / 换措辞 / 改 match-max 全都没用**——这三个旋钮都不动「画布对齐」这一项。`match`/`max` 只改采样密度，不改占位。
5. **编码端确实也太抠**：1088×1920 全身立绘里，头+发实测 201×342px = 全图 **3.29%**，在 `max` 下（原样直通 2040 token）只分到 **67 token（6.3×10.7 格）**。而 `match` 会把它压到 480×832=390 token ⇒ 头只剩 **13 token**，是 `max` 的 19%。**你已经开对了 `max`。**
6. **解码端是另一个独立瓶颈**：480p 下中景人物的脸只有 **3.8 个 token 高**（MCU 5.0 / 特写 7.5）。**升 768p 把脸高从 3.8 提到 6.0 token（+58%），是当前性价比最高的一刀**，且 `max` 下代价仅 +8%。
7. **提示词结构另有一处独立违规**（与分辨率无关）：`0044_参考视频.md` 给纯人物参考图建了独立 `<Picture 1>` 条目，官方 `ref-en.txt` L68 明令禁止；社区文档称之为身份漂移的**第 1 顺位原因**。
8. **推荐人物参考图规格：与生成画幅同宽高比的横构图中近景**，如 2048×1152（16:9）。此时头占 426 token（现状的 6.4×）、画布重叠 99%、头落在画面内 y=0.147。
   ⚠️ **不要用方形 2048×2048**：它只有 76% 重叠，且头落在 y=0.030（贴画面上缘）。方图裁进 16:9 会切掉上下、把头顶推到边界。

## 1. 机制：面积归一化的 RoPE 画布

### 1.1 源码

`ComfyUI/comfy/ldm/minimax/model.py` L70-74：

```python
def _axis_from_sqrt_area(dim, patch, sqrt_area):
    # linspace((1 - ratio) / 2, (1 + ratio) / 2, dim // patch, endpoint=False) * 32
    ratio = dim / sqrt_area
    n = dim // patch
    return (torch.arange(n, dtype=torch.float64) * (ratio / n) + (1.0 - ratio) / 2.0) * 32.0
```

参考图与视频帧都走同一个函数（`_frame_grid` L88-92；参考图段见 `PackedLayout` L399-408），**各用自己的 (h, w) 生成自己的网格，但都落在同一个归一化坐标系里**。

### 1.2 关键性质

对任意尺寸，每条轴的取值区间恒为 `[(1−r)/2, (1+r)/2]`，其中 `r = dim / √(w·h)`：

| 尺寸 | r_y | 归一化画布 y 区间 | r_x | 归一化画布 x 区间 |
|---|---|---|---|---|
| 参考图 1088×1920 | 1.328 | **[−0.164, 1.164]** | 0.753 | [0.124, 0.876] |
| 目标帧 832×480 | 0.760 | **[0.120, 0.880]** | 1.317 | [−0.158, 1.158] |

由此得两条结论：

- **r 是量纲无关的**：竖图的 r_y=1.328 和 4K 竖图完全一样。**缩略图不会「变窄条」**——任何尺寸的参考图都撑满同一条归一化区间。（本文档纠正了此前一轮基于「fraction × ratio 线性外推」的误算。）
- **画布长宽比 = (1+r) / (1−r)**，是宽高比的**单调函数**。所以**尺寸只影响采样密度（token 数），不影响「占画面多大」；后者只由宽高比决定**。

### 1.3 重叠度：把失配量化成一个数

参考图画布矩形与目标画布矩形的交集面积占比（以参考图面积为 1）：

```
overlap = min(r_y1, t_y1) − max(r_y0, t_y0)   （y 轴，负数记 0）
        × min(r_x1, t_x1) − max(r_x0, t_x0)   （x 轴）
```

**这是本文档最有用的一句话：`overlap = 1` 意味着参考图主体按原比例落进目标帧；`overlap < 1` 意味着被裁掉的恰好是构图的一部分。**

## 2. 本工作流的实测数据

### 2.1 参考集与目标画布

目标画布：`MiniMaxH3ReferenceToVideo` widgets `["", 832, 480, 124, "max"]` ⇒ **832×480，ratio 1.733，124 帧 / 15 s**，`ref_image_size = max`。

| 参考 | 文件 | 尺寸 | ratio | token（max） | **画布重叠** |
|---|---|---|---|---|---|
| `<Picture 1>` **人物** | `media/七纹刻印/0011_万物建模/00001_陈落.png` | 1088×1920 | 0.567 | 2040 | **57%** |
| `<Picture 2>` 场景左前 | `media/七纹刻印/0035_场景截帧/00001_书房_左前.png` | 832×480 | 1.733 | 390 | **100%** |
| `<Picture 3>` 场景后左 | `media/七纹刻印/0035_场景截帧/00001_书房_后左.png` | 832×480 | 1.733 | 390 | **100%** |

> **场景 100%、人物 57%——这就是「场景遵从很完美、人物遵从很差」的完整解释。**
> 失配倍数 = (832/480) ÷ (1088/1920) = **3.06×**。

### 2.2 头落在画面之外

人物立绘的头+发在原图 y = 54…395（占原图高度 2.8%…20.6%）。映射到归一化坐标：

```
coord(f) = f × r_y + (1 − r_y) / 2
y_top    = 0.0281 × 1.328 + (1 − 1.328)/2 = −0.127
y_bottom = 0.2057 × 1.328 + (1 − 1.328)/2 = +0.109
目标帧 y 区间 = [0.120, 0.880]
```

**y_bottom = 0.109 < 0.120 ⇒ 整颗头（连同部分肩）在目标画面之外。** 模型拿到的画面里没有头，只能靠提示词里的文字描述重造一张脸——这就是 0.5 的来源。

### 2.3 编码端 token 预算

token 网格 = 每 **32×32 像素** 1 个 token（VAE `//16` 下采样 + patchify `(1,2,2)`；源码 `nodes_minimax_h3.py` L311 `"latent_h": th // 16`、`model.py` L42）。

`00001_陈落.png` 实测（掩膜限定在头部包围盒 `x∈[380,720], y∈[0,420]` 内，避开手臂与短裤；bbox 已画回原图目视校验）：

| 项 | 实测值 |
|---|---|
| 主体 bbox | x 276–819, y 52–1858（占高 94.1%，标准全身立绘） |
| **头+发 bbox** | **x 442–642, y 54–395 = 201×342 px** |
| 占全图 | **3.29%** |
| **token** | (201/32)×(342/32) = 6.3×10.7 ⇒ **67 token** |
| 全图 token（max，scale=1.000） | 2040（2048 短边封顶值的 25%） |

### 2.4 `match` vs `max`：你已经开对了

源码 `nodes_minimax_h3.py` L300-306：

```python
if ref_image_size == "match":
    scale = min(1.0, math.sqrt((width * height) / (w * h)))   # 面积对齐生成画布，只缩不放
else:
    scale = min(1.0, REF_IMAGE_SHORT_EDGE / min(w, h))       # 短边 2048，只缩不放
```

代入本例（生成画布 832×480，`REF_IMAGE_SHORT_EDGE = 2048`，L32）：

| 口径 | scale | 实际尺寸 | token | **头 token** |
|---|---|---|---|---|
| `match` | 0.4372 | 480×832 | 390 | **13** |
| `max` | 1.0000 | 1088×1920 | 2040 | **67** |

**`match` 只给 `max` 的 19%。当前配置已经正确，不要改。**

> ⚠️ 修正记录：此前一轮曾报「脸只分到 43 token（205×215px）」，该 bbox 取错（用错了非头部区域），正确值为 **67 token（201×342px）**。

### 2.5 解码端硬约束

解码出的 480p 画面里，脸能占多少 token 由**镜头景别 × 输出分辨率**共同决定：

| 生成档 | 中景（脸高 25%） | MCU（33%） | 特写（50%） |
|---|---|---|---|
| **480p**（当前） | 120px / **3.8 tok** | 158px / 5.0 | 240px / 7.5 |
| **768p** | 192px / **6.0 tok** | 253px / 7.9 | 384px / 12.0 |
| 1080p | 272px / 8.5 | 359px / 11.2 | 544px / 17.0 |

**即使参考图无限高清，解码端也只有 3.8 个 token 高来还原骨相。** 这是与 §2.3 完全独立的第二个瓶颈。

### 2.6 符合宽高比之后

| 方案 | 尺寸 | ratio | 重叠 | 头 token | 头落点 |
|---|---|---|---|---|---|
| **现状** | 1088×1920 | 0.567 | 57% | 67 | y = −0.127 **（画面外）** |
| **推荐** | **2048×1152 中近景** | 1.778 | **99%** | **426** | y = 0.147 ✅ |
| 次选 | 1536×864 中景 | 1.778 | 99% | 229 | y = 0.147 ✅ |
| ⚠️ 避免 | 2048×2048 方图 | 1.000 | 76% | 937 | y = 0.030 ⚠️ 贴边 |

## 4. 提示词结构违规（独立于分辨率）

`stories/七纹刻印/0044_参考视频.md` 给纯人物参考图建了**独立**条目：

```
<Picture 1>(<Subject 1> appearance reference):fully_preserved
```

官方 `refs/MiniMax-H3/skills/h3-prompt-writing/references/ref-en.txt` **L68** 明确规定：

> 纯定义角色的参考图**不得**建独立 `<Picture N>`，必须写进对应的 `<Subject N>`。`<Picture N>` 仅用于**首帧 / 关键帧 / 尾帧 / 构图锚点**。

社区排障文档进一步指出，identity drift 的**第 1 顺位原因**就是把身份图放进独立 `<Picture N>` 而非 `<Subject N>`：

> Do not recommend sheets. Use separate full-resolution photographs, two to four of them.
> — [teskor-hub/minimax-h3-skill · troubleshooting.md](https://raw.githubusercontent.com/teskor-hub/minimax-h3-skill/main/references/troubleshooting.md)

> **Scale sets the ceiling** — 一厘米宽的胎记在广角镜里只是几像素。小而低对比的特征最先被抹成平均脸。
> — [teskor-hub/minimax-h3-skill · reference-mode.md](https://raw.githubusercontent.com/teskor-hub/minimax-h3-skill/main/references/reference-mode.md)

同源建议（reference-mode.md）：按 body landmark 定位 + 测量式描述（「falls to the collarbone」而非「long hair」）；**三到八条具体细节优于形容词段**。

## 6. 关于「0.92」的目标：先做语义校正

用 ArcFace `w600k_r50` 余弦相似度时，必须知道它在**什么口径**下测：

- **同一张脸的任意退化**（压缩/调色/轻度模糊）**任何时候都 ≥ 0.93**；
- **同一角色换一张画面**（换机位、换表情、换光线）**立刻掉到 0.3~0.6**；
- 本项目实测：**参考图自身正视 vs 侧视 = 0.4071**。

⇒ **0.92 / 0.95 落在「同一角色不同画面」的区间**，这与「同一张脸」不是一回事。以此为验收标准时，生成端**全时段 0.92+ 不可达**。

可行路径（按可信度）：

1. **关键帧锚定**：你 2026-09-18 实测 SSIM 上限 0.83~0.92。关键帧帧本身由用户选帧控制相似度，中间帧由模型插值 ⇒ 是当前最现实的手段。
2. **后处理硬贴**：可达 0.978，但观感崩坏，不建议批量用。
3. 参考图 → 多角度图集（两到四张独立全分辨率照片，不拼版）走 Ref2VA，是官方推荐的跨镜头同一人物路线；[I2VA 只保大致身份](https://raw.githubusercontent.com/Rimagination/h3lite/main/references/face-quality.md)。

## 7. 复跑方法

所有数字按下列公式复算，**无随机性**：

```
# max / match 缩放（nodes_minimax_h3.py L300-306）
scale = min(1.0, 2048/min(w,h))                      # max
scale = min(1.0, sqrt(W*H/(w*h)))                     # match
tw = round(w*scale/32)*32 ; th = round(h*scale/32)*32
token = (tw//32) * (th//32)

# 归一化画布（model.py L70-74）
r  = dim / sqrt(w*h)
span  = [ (1-r)/2 , (1+r)/2 ]
coord(f)   = f*r + (1-r)/2          # 图内比例 -> 归一化坐标
frac(c)    = (c - (1-r)/2) / r      # 逆映射

# 画布重叠
overlap = max(0, min(r1,t1)-max(r0,t0))_x * 同式_y

# 解码端脸高 -> token
face_px = frame_height * 景别占比   # 中景 .25 / MCU .33 / 特写 .50
face_tok = face_px / 32
```

头 bbox 的像素测量脚本见 §10（掩膜须限定在 `x∈[380,720], y∈[0,420]` 头部包围盒内，否则会把手臂皮肤误判为人、把灰短裤误判为头；bbox 应画回原图目视校验）。

## 8. 一句话回答原始问题

> **「为什么传 1088×1920 高清图、开 max，人物还是只有 0.5？」**
>
> 因为 `max` 保证了**密度**（2040 token，2048 封顶的 25%），却完全不管**占位**。
> 0.567 的竖幅立绘落在 1.733 的横版画布上，画布只重叠 57%，

>
> 模型看到的画面里**没有脸**。它只能靠提示词重造一张脸，所以是 0.5。
> 场景图之所以完美，是因为它们本来就是 832×480，与画布 100% 重合。
