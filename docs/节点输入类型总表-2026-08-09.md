## 附:这些类型标识是什么?为什么都是大写、不是 Python 类型?

**ComfyUI 的节点输入"类型" = 一个自定义的字符串标识,不是 Python 类型,也不做强制转换。**

### 机制

节点在 `INPUT_TYPES()` 里声明输入,每个输入是 `("类型标识", {配置})`:

```python
@classmethod
def INPUT_TYPES(cls):
    return {
        "required": {
            "image": ("IMAGE", {"tooltip": "..."}),   # "IMAGE" 只是字符串
            "steps": ("INT", {...}),                  # 不是 Python 的 int
            "enabled": ("BOOLEAN", {...}),
            "mode": (["a", "b", "c"], {...}),         # 列表 = 下拉选项, 不是类型
        }
    }
```

| 层面 | 类型字符串的作用 |
|---|---|
| **画布连线校验** | 上游输出类型字符串 == 下游输入类型字符串 → 允许连线;`*` 与任何类型都匹配 |
| **前端控件** | 决定画什么控件:`INT`→数字框、`BOOLEAN`→复选框、`STRING`→文本框、列表→下拉 |
| **运行时** | **几乎不起作用** —— `execute` 收到上游实际返回的 Python 对象,类型字符串不拦截、不转换 |

### 关键点

- `execute(image, steps, enabled)` 里 `image` 实际是 torch 张量/numpy 数组,`steps` 是 Python `int`,`enabled` 是 Python `bool`;
- **类型字符串不会强制**这些:"INT" 端口接了返回字符串的上游节点,ComfyUI 不会报错(校验只看字符串匹配),执行时拿到什么就是什么;
- 所以类型字符串是**给连线和前端看的契约**,真正的 Python 值在执行时才流过来。

### 大写只是惯例,可自定义

- 大写是社区约定,非强制。任何节点都能发明新字符串类型(如 `GJJ_BATCH_IMAGE`、`WANVIDEOMODEL`、`FALLINGTS_MD_TABLE`)——两个插件用同一个字符串即可互相连线;
- `FALLINGTS_MD_TABLE` 这类自定义类型还兼任**前端自定义控件触发键**:前端 `getCustomWidgets()` 按它渲染 DOM 控件。

### 特殊写法

| 写法 | 含义 |
|---|---|
| `"*"` | 通配 ANY,与任何类型可连(插件用 `AnyType(str)` 覆写 `__ne__` 恒 False 实现) |
| `"IMAGE,MASK"` | 逗号分隔 = 该端口可接收其中任意一种(校验取交集) |
| `["a","b",...]` | 不是类型,是下拉选项列表(COMBO) |
| V3 `IO.ComfyNode` 的 `IO.Image/IO.Video` | V3 规范封装,底层仍映射到同一套字符串标识 |

### "真实类型"在哪

1. **前端**:每种字符串类型对应默认端口颜色 + 控件(配置在 `extensions/core/typeConfig.js`,插件可覆盖);
2. **你的代码**:节点自己约定 —— `"INT"` 端口按约定传 Python `int`,`"IMAGE"` 传张量。**是人和节点之间的约定,不是系统强制**。

> 一句话:大写类型标识 = ComfyUI 的"电路图标注",负责连线和控件;真正的 Python 值在执行时才流过来,由每个节点自己决定传什么。
