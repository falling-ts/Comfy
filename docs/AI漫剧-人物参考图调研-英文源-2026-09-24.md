# Character Reference Images for AI Video: Single Full-Body vs. Close-Up + Turnaround vs. Many Close-Ups + Turnaround

Research report. English-language sources. Every claim carries a clickable URL and a label:
**[M]** = measured/tested (numbers, ablation, controlled comparison) · **[O]** = official vendor statement/API constraint · **[A]** = anecdote/opinion/single impression.

---

## ① Summary of conclusions

### A. The two pipelines must be separated, because the answer differs

**I2V (single first frame).** The first frame is simultaneously the identity anchor *and* the composition anchor, and models are documented to carry the frame's background, pose and layout into the motion. SkyReels-A2 states plainly that I2V "is often constrained by the 'copy-paste' dependency on the initial frame" [M]. Consequently:
- The relevant choice for I2V is **framing of that one frame**, not reference count. A full-body first frame spends few pixels on the face; a bust/medium close-up spends many. The only vendor-authored guidance found on this point says a "medium close-up or 'bust' shot is typically superior to a full-body shot for the master reference, as it allocates more pixels to the face," and that the head should occupy 25–35% of frame [A, vendor heuristic, self-declared non-empirical].
- **A turnaround/character sheet is structurally unusable as an I2V first frame.** A sheet is a composite of several views; feeding it as frame 1 makes the layout itself the composition. The practitioner tool that builds sheets explicitly turns burned-in labels off because "burnt-in text sits over the subject and follows the frame into anything that reuses it" [A].
- Wan 2.2 Animate Mix is the cleanest official example: it accepts **exactly one** character image plus a driving video, and its own FAQ guidance is to "frame the character consistently in both the input image and the reference video" and "keep body proportions consistent" [O].

**Ref2V (subject identity anchoring).** Here the multi-view turnaround is the *designed* input, not a workaround:
- Kling's own Element Library describes the mechanism as uploading **multi-angle reference images** so the model "remembers" the character, and states video generation supports up to **7** reference elements (images up to **10**) [O].
- Vidu's reseller documentation for **Q2 Reference2V** states **up to 7 reference images** and instructs: "provide different angles of the same character (front, profile, back) to help the AI understand the 3D volume of the subject" [O].
- Runway Gen-4 References supports **up to three** reference images, encoded "at the entity level" [O, via two secondary mirrors].
- **But** the academic record shows naive multi-view conditioning is not free: MV-S2V documents that existing mechanisms — "concatenating references along the frame dimension, or compositing references on a single image" — "fail to distinguish" *different subjects* from *different views of the same subject* [M]. That is the formal statement of the "model treats the views as separate people" failure mode.
- The measured gain from adding views is **real but modest and model-dependent**: on MV-S2V's benchmark, Phantom multi-view vs single-view moved DINO v→r from 0.773 → 0.788 and 3D-consistency Met3r from 0.148 → 0.123 (lower better); MAGREF barely moved (0.635 → 0.637) [M].

### B. Face close-ups vs. full-body

- Vendor heuristic favours a **close-up/bust** for the master reference (pixels-on-face argument) [A].
- Architecture-level evidence that the face is treated as a distinct identity channel: Phantom-Data's data pipeline represents a person as a **concatenation of a general appearance embedding and an ArcFace facial embedding**, and ConceptMaster's pipeline **discards human crops that contain no face region** ("removing humans where only the body parts are visible") [M — as a design/measurement choice, not an ablation].
- No source found ran a controlled close-up-vs-full-body identity-similarity ablation for a video model. This is a genuine gap, not a settled answer.

### C. "More references ≠ better"

Concrete, non-marketing evidence exists, and it is consistent across four independent mechanisms:
1. **Attribute mixing / identity decoupling** — ConceptMaster: "directly adopting existing customization methods inevitably mix attributes when handling multiple concepts simultaneously" [M].
2. **Layout and background leakage + pose freezing** — RefDrop: "applying RFG to all the self-attention blocks can lead to the leakage of spatial layout and background from the reference image, causing the generated objects to have quite similar poses and backgrounds"; quantified over 1100 images (11 blocks × 20 sets × 5 images, DreamSim + LPIPS), and fixed by excluding the first upsampling block [M].
3. **Motion freeze from too-strong reference influence** — RefDrop: "A coefficient of 0.2 generally suffices, and a larger coefficient may make the video totally static" [M].
4. **Copy-paste of context** — Phantom-Data: in-pair reference sampling "inherently entangles subject identity with background and contextual attributes"; measured as the tradeoff In-pair DINO **0.478** / Reward-TA **2.074** vs. their cross-pair DINO **0.416** / Reward-TA **3.827** — i.e. tighter identity against *worse* prompt-following [M].

### D. Anime / stylized specifics

- The only anime-specific vendor guidance found argues **against** multiple references: "our internal testing shows that a single, high-fidelity 'Master Reference' yields superior results. Using multiple images often introduces subtle variances in facial geometry or costume details that the S2V engine struggles to reconcile," attributing flicker to "multi-image noise" [A, vendor, self-declared non-empirical].
- Practitioner sheet construction for a stylized/anime-capable pipeline uses a hard-cut turnaround: **full body → face close-up → left profile → right profile → back**, one ~1 s static view each, with generous margin so wings/tails/props are not cropped [A].
- **No quantitative anime/comic 3-view-vs-1-view study, and no LoRA-dataset view-count ablation, was found.** Anime character-sheet advice in the wild is practitioner convention, not measurement.

### E. Blunt note on source quality

The search surface for this question is **dominated by machine-generated SEO content and vendor "knowledge base" filler**. Multiple prominent results (Hailuo's own "Field Notes" pages, `seedance.tv`, `invideo.io/faq/*`, `pikalabsai.org`, `wan27.org`, `apatero.ai`) either self-declare that their numbers are not from controlled studies, or are unattributed listicles. The Hailuo pages go as far as citing the NIST AI Risk Management Framework and the Stanford AI Index as support for hand-consistency advice, and one page carries the disclosure: "This is a qualitative analysis of common patterns, not a controlled laboratory study." Vendor API references and the academic papers are the load-bearing sources here; everything else is labelled anecdote below.

## ③ Contested points

1. **Close-up vs. turnaround, from the same vendor.** MiniMax/Hailuo publishes both "a medium close-up or bust shot is typically superior to a full-body shot" and "the most common mistake… is using a single, static headshot; provide 3–4 angles in a single reference frame" — and, on its anime page, "a single, high-fidelity Master Reference yields superior results" over multiple images. Three mutually inconsistent positions across four pages on the same domain. All three are labelled by the publisher as heuristics rather than measurements.

2. **Does adding views help?** MV-S2V's own benchmark shows multi-view beating single-view clearly for Phantom (+0.015 DINO, −0.025 Met3r) and essentially not at all for MAGREF (+0.002 DINO, −0.001 Met3r). AlcheMinT claims graceful scaling to "an arbitrary number of input views"; MV-S2V claims existing mechanisms cannot even distinguish a view from a subject without a bespoke encoding. Both are defensible because they describe different conditioning architectures.

3. **Turnaround vs. single image in Ref2V.** Vidu's documentation instructs supplying front/profile/back "to help the AI understand the 3D volume"; Kling's mechanism is built around multi-angle uploads; Runway's own copy says consistency works "even when working from a single reference image"; Kling also auto-synthesises extra views from one image. The vendors are simultaneously selling multi-view input and single-image sufficiency.

4. **Does the sheet layout actually leak?** The strongest evidence that composite/grid references leak their layout is (a) RefDrop's measured spatial-layout leakage in the *image* domain, and (b) practitioner warnings about burned-in labels. I found **no** controlled video-model test that feeds a 3-panel turnaround sheet and measures panel/border/text leakage. The failure mode is well-attested anecdotally and mechanistically plausible, but not measured for video.

5. **Identity fidelity vs. prompt adherence is a genuine tradeoff, not a bug.** Phantom-Data's numbers show the identity-aligned (in-pair) configuration wins on DINO while losing badly on Reward-TA. "Best identity" and "best video" are different objectives, so "more/better references" can move the two metrics in opposite directions.

6. **The `@image1`-style explicit binding question.** Two independent sources describe explicit per-reference labelling (Runway's `image_1`/`image_2`/`image_3` prompt convention; Seedance's `@image1` syntax), and MV-S2V/AlcheMinT both add *learnable per-reference index embeddings* and *word tags* to disentangle references. This converges on: unlabelled multi-reference input is ambiguous, and the ambiguity is architectural, not merely a prompting skill issue.
