# ComfyUI 节点定义与前后端绑定

日期:2026-08-08
关联插件:ComfyUI-FallingTS(`FallingTSContinue` / `FallingTSRoute` 等)
相关源码:`ComfyUI/server.py`、`ComfyUI/nodes.py`、前端打包 `comfyui_frontend_package/static/assets/api-*.js`

本文讲清楚:节点是怎么"定义"的、前端怎么拿到定义、前后端靠什么绑定、节点 ID 是什么形态、一个节点用 JSON 怎么表现。

---

## 一、节点"定义"有两层,别混

| 层 | 在哪定义 | 形态 |
|----|---------|------|
| **节点的"长相"**(几个输入/输出/什么类型/分类/默认值) | **后端 Python**(`INPUT_TYPES()` / `define_schema()`) | 由后端序列化成 JSON |
| **节点在工作流里的"实例"**(摆哪、连了谁、参数值) | **工作流 JSON 文件** | 纯 JSON |

前端**不读 Python**,也不解析工作流里的"定义" —— 它通过 **`GET /object_info`** 向后端要定义:

- `server.py:800-811`:`/object_info` 遍历 `NODE_CLASS_MAPPINGS`,对每个类调 `node_info(x)`(`server.py:751-798`)把 Python 属性(`INPUT_TYPES/RETURN_TYPES/CATEGORY/DESCRIPTION/...`)拼成 JSON 返回
- 前端 `api.getNodeDefs()`(`api-DepWbifE.js`)拉这个 JSON,作为节点定义(含每个输入的类型、默认值、下拉选项等)

所以前端看到的"节点面板" = 后端 `node_info()` 生成的 JSON。

### node_info() 拼了什么(`server.py:751-798`)

```python
info['input']        = obj_class.INPUT_TYPES()        # 输入定义(required/optional/hidden)
info['output']       = obj_class.RETURN_TYPES         # 输出类型
info['output_name']  = obj_class.RETURN_NAMES         # 输出名
info['name']         = node_class                      # 类名
info['display_name'] = NODE_DISPLAY_NAME_MAPPINGS[...] # 显示名
info['description']  = obj_class.DESCRIPTION
info['category']     = obj_class.CATEGORY
info['output_node']  = obj_class.OUTPUT_NODE           # 是否输出节点(partial 目标判定用)
info['python_module']= obj_class.RELATIVE_PYTHON_MODULE
info['search_aliases'] = getattr(obj_class, 'SEARCH_ALIASES', [])
...
```

## 二、前端怎么拿定义

```
前端启动
  → api.getNodeDefs() → GET /object_info
  → 得到 { "节点类名": {input, output, display_name, category, ...} }
  → 作为"节点定义"缓存,画节点面板/校验输入都用它
```

**关键:前端拿的是 JSON,不是 Python。** 这个 JSON 的"源头"是后端 Python 类(`INPUT_TYPES()` 等),由 `/object_info` 在运行时序列化。

## 三、前后端绑定 —— 靠 `type`(类名)

**绑定键是节点的 `type`,即后端 `NODE_CLASS_MAPPINGS` 的 key**:

```
前端 LGraphNode.type = "FallingTSContinue"
        │  (graphToPrompt)
        ▼
POST /prompt → {"43": {"class_type": "FallingTSContinue", "inputs": {...}}}
        │
        ▼
后端 execution: class_type → nodes.NODE_CLASS_MAPPINGS["FallingTSContinue"]
        → 找到类 → 实例化 → 调 FUNCTION="execute"
```

- 前端创建节点:用 `type` 去 `/object_info` 返回的 JSON 里查定义,画输入输出口
- 运行时:`graphToPrompt`(`settingStore`)把每个节点转成 `{id: {class_type: type, inputs}}`
- 后端:`execution.py:444-445` `class_type = ...["class_type"]; class_def = nodes.NODE_CLASS_MAPPINGS[class_type]`

## 四、节点 ID:两个形态

| 位置 | 形态 | 例子 |
|------|------|------|
| **工作流 JSON / 画布** | **整数** `id` | `"id": 43` |
| **prompt(`POST /prompt`)** | **字符串** key | `"43"`(JS 对象键恒为字符串) |
| **后端执行** | 字符串 `unique_id` | `"43"` |

后端全程用**字符串 id**:

- `execution.py:440` `unique_id = current_item`(= prompt 的 key)
- 缓存键、ExecutionList、hidden `UNIQUE_ID` 都是它
- 继续节点 `_data_cache["43"]` / `_released` 用的就是这个字符串;前端 `/proceed/continue/43`(`node.id` 是整数,但 URL 参数读出来是字符串 `"43"`)→ 两边能对上

## 五、一个节点的 JSON 表现(工作流里真实节点 #43)

### 5.1 工作流 JSON 里的继续节点

```json
{
  "id": 43,                          // ← 整数 ID
  "type": "FallingTSContinue",       // ← 绑定键 = NODE_CLASS_MAPPINGS key
  "pos": [5320, 150],                //   画布坐标
  "size": [230, 90],
  "order": 50,                       //   执行顺序
  "mode": 0,                         //   0=启用
  "inputs": [
    { "name": "any", "type": "*", "link": 15076 }   // link=连到哪条线
  ],
  "outputs": [
    { "name": "any", "type": "*", "slot_index": 0, "links": [15067] }
  ],
  "title": "继续: 分块前",
  "properties": { "Node name for S&R": "FallingTSContinue", "proceedState": "rerun" },
  "widgets_values": [null]
}
```

### 5.2 前端 `graphToPrompt` 转成 prompt(提交给后端)

```json
{
  "43": {                                    // ← 字符串 ID(整数变字符串)
    "class_type": "FallingTSContinue",       // ← 类名
    "inputs": {
      "any": [19, 0]                         // ← 连线输入: [来源节点id, 来源槽]
    }
  }
}
```

KSampler 例子(带连线输入):

```json
{
  "16": {
    "class_type": "KSampler",
    "inputs": {
      "model": [4, 0],
      "positive": [5004, 0],
      "latent_image": [4001, 0],
      "steps": [5101, 1],
      "cfg": [5101, 2]
    }
  }
}
```

连线输入是 `[来源节点id, 来源槽]`;widget 参数(如 KSampler 的 steps/cfg)可通过分组开关/原语节点的连线传进来,也可作为 `widgets_values` 存于工作流 JSON。

## 六、一句话总结

> **定义 = Python(`INPUT_TYPES`)→ `/object_info` 序列化成 JSON 给前端;前端只认这个 JSON + 工作流里的实例 JSON。绑定 = 节点的 `type`(类名)对上后端 `NODE_CLASS_MAPPINGS`。ID = 工作流里整数 `43`,prompt 里字符串 `"43"`,后端全程用它当 `unique_id`。**
