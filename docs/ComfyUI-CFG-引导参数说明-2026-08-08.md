# ComfyUI CFG(Classifier-Free Guidance)引导参数说明

日期:2026-08-08
关联:Qwen-Image 文生图工作流(段0 分组开关 4步/20步 模式)
相关源码:`ComfyUI/nodes.py:1597`、`ComfyUI/comfy/samplers.py`(cfg_function)

本文说明 CFG 是什么、取值范围、以及随着 CFG 升高画面如何变化,并给出 Qwen 工作流的实际建议。

---

## 一、CFG 是什么

**CFG(Classifier-Free Guidance,无分类器引导)** = 采样时的 `cond_scale`,控制**正提示词 vs 负提示词**的平衡。

### 核心公式(`comfy/samplers.py` cfg_function)

```python
cfg_result = uncond_pred + (cond_pred - uncond_pred) * cond_scale
```

- `cond_pred` = 按正提示词(conditioning)预测的去噪结果
- `uncond_pred` = 按负提示词(空/negative)预测的
- `cond_scale` = **CFG 值**

> **CFG 放大的是"正负提示词之间的差异"。CFG 越大,结果越偏向正提示词、越偏离负提示词。**

## 二、取值范围

| 项 | 值 | 说明 |
|----|-----|------|
| UI 声明(`nodes.py:1597`) | `min=0.0, max=100.0`,默认 8.0,step 0.1 | 滑块限制 |
| 公式层面 | **无界浮点数** | 手动填 >100 也能跑;负值 = 反向引导 |
| 负值(<0) | 引导**远离**正提示词 | 一般不用 |

## 三、不同取值 → 画面变化(从低到高)

| CFG | 公式行为 | 画面表现 |
|-----|---------|---------|
| **0** | `= uncond_pred`,无引导 | 只看负向,基本随机/负向内容 |
| **0.5** | 一半引导 | 软、糊、跟提示词弱 |
| **1.0** | `= cond_pred`,**纯正提示词、负向完全无效** | Lightning 蒸馏常用;干净但"平",无负向压制 |
| **2.5** | 中等引导 | 开始跟提示词,但复杂布局/负向还不够强 |
| **3~4** | 较强引导 | **通常最佳平衡区**(Qwen 普通模型常用) |
| **8~12** | 强引导 | 跟得紧,但开始**过度承诺**:过饱和、对比强、细节发"烤焦/塑料感"、背景崩 |
| **20~50** | 极强 | 构图锁死但明显伪影、色彩过爆、画面僵硬 |
| **100** | 上限 | 通常一坨过曝/噪点 |

### 关键:倒 U 形曲线

**不是越高越好,而是倒 U 形**:

```
    画质 / 跟随度
        ▲
    ▲   │      ▲
   │    │       │   ← 甜区 3~4
  │     │        │
 低    2.5      4+      100
跟不住         崩(过曝/伪影)
```

- 太低 → 跟不住提示词(软、丢布局)
- 甜区(~3~4)→ 跟得住且干净
- 太高 → 画质崩(过曝、塑料感、伪影)

## 四、对 Qwen 文生图工作流的实际建议

### 段0 分组开关(5101)两种模式

| | 4步模式(switch=True) | 20步模式(switch=False) |
|---|---|---|
| 模型 | Qwen-Image + **Lightning-4steps LoRA** | **纯 Qwen-Image(无 Lightning)** |
| 步数 | 4 | 20 |
| **CFG** | **1.0** | **2.5** |

### 结论

1. **Lightning 蒸馏模型**已把"提示词→构图"映射压进 4 步,CFG **1.0 就够**(纯正提示词、无负向拉扯),更高反而出伪影。
2. **普通模型跟住复杂布局需要更高 CFG(3~4)**;20步模式 CFG 2.5 偏低 → 只兑现最主体指令(三视图)、丢次要区域(左侧特写)。
3. **想让 20步 跟住"特写+三视图"布局**:把 CFG 从 2.5 提到 **3.5~4** 试 —— 未到画质崩的区间。
4. CFG 升高会让**负提示词也更生效**:工作流负向写了"变形/多余肢体/背景杂乱"等,CFG 提高后负向压制增强,顺带压掉"三视图多画脸/多余肢体"。
5. 若 CFG 到 4 仍丢特写 → 不是 CFG 问题,是布局对普通模型太难,该靠**特写脸 reference / 分区域生成**解决。
