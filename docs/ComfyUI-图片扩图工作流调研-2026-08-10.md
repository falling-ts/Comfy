## 一、什么是扩图(Outpainting)

扩图指在一张已有图片的外围扩展画布,生成与现有内容风格一致的新画面,常用于:

- **场景扩展**:把一张特写向外扩,展现更完整的场景环境
- **构图调整**:扩画布优化构图,改变画面比例(如 1:1 扩到 16:9 做海报)
- **内容补充**:在画布边缘补充新元素(如给产品图补场景背景)

扩图本质是**基于掩码(mask)的局部重绘**,与 Inpainting(内补)核心机制相同,差别只在掩码的构建方式——扩图用 `ImagePadForOutpaint` 节点自动把画布外扩一圈,外扩区域即掩码区域。

---

## 二、核心节点(原理)

| 节点 | 作用 | 备注 |
|------|------|------|
| **ImagePadForOutpaint** | 按 `left/top/right/bottom` 四方向外扩画布,`feathering` 控制原图与扩展区的过渡平滑度;输出外扩后的 `image` + 标记扩展区的 `mask` | 所有扩图方案的基础,几乎所有扩图流程都含它 |
| **InpaintModelConditioning** | 把原图 + mask + prompt 编码为 inpaint 模型的条件(latent),负向条件用 `ConditioningZeroOut` 置零,让模型只重绘掩码区域 | FLUX.1 Fill 系列专用 |
| **DifferentialDiffusion** | 让去噪只在掩码区域生效(非掩码区 denoise=0),保证原图区域不被改动 | FLUX.1 Fill 系列搭配使用 |
| **ControlNetInpaintingAliMamaApply** | 阿里妈妈 Inpaint ControlNet 的应用节点:把原图 + mask 送入 ControlNet 引导扩散 | InstantX/Qwen-Image、alimama/Flux 系列用 |
| **ControlNetLoader** | 加载 Inpaint 类 ControlNet(InstantX Qwen-Image / alimama Flux) | |
| **FluxKontextImageScale** | 用 Lanczos 把输入图缩放到 Kontext 模型训练尺寸(17 档宽高,见官方文档),避免大图导致多主体等劣化 | FLUX Kontext / FLUX.2 系列用 |
| **ImageCompositeMasked** | 把去噪生成的扩展区与原始图按 mask 合成,还原未改动部分 | 多数方案的后处理 |
| **SetLatentNoiseMask / GrowMask** | 在 latent 上施加掩码 / 掩码膨胀,控制重绘范围 | Qwen 系列方案用 |

## 四、方案详解

### 方案 1:Qwen-Image + InstantX Inpainting ControlNet(中文社区主流)

**来源**
- 官方蓝图:`ComfyUI/blueprints/Image Outpainting (Qwen-Image).json`(子图封装)
- 官方模板:`templates/图像/image_qwen_image_instantx_inpainting_controlnet.json`(含 inpaint / outpaint 两个子图)
- webs\RunningHub:`二次元/扩图Qwen Image InstanX_加速版_双节棍版本.json`(虾仁不瞎,168 赞 / 3518 次运行,2026-06-26);`插件/🥨千问 QwenImage InstantX ControlNet 外扩图片🥨.json`(炮老师,2025-09-12)
- 官方 ControlNet 模型页:https://huggingface.co/InstantX/Qwen-Image-ControlNet-Inpainting

**模型清单**
| 文件 | 位置 | 说明 |
|------|------|------|
| `qwen_image_fp8_e4m3fn.safetensors` | diffusion_models | Qwen-Image 20B fp8(本机为 2512 版,基础版可混用) |
| `InstantX_Qwen-Image-ControlNet-Inpainting.safetensors` | controlnet | **InstantX 训练的 Inpainting ControlNet**:6 个 double block 拷贝自 Qwen-Image transformer,65K steps / 1000 万高清图 / 1328×1328 训练;支持物体替换、文字修改、背景替换、Outpainting |
| `qwen_2.5_vl_7b_fp8_scaled.safetensors` | text_encoders | Qwen 多模态文本编码器(本机已有) |
| `qwen_image_vae.safetensors` | vae | 本机已有 |
| `Qwen-Image-Lightning-4steps-V1.0.safetensors`(或 8steps V1.1) | loras | 加速 LoRA |

**流程**
1. `LoadImage` → `ImagePadForOutpaint`(设 left/top/right/bottom 外扩像素,feathering 平滑过渡)
2. `ControlNetLoader`(InstantX ControlNet)+ `VAEEncode`(原图)→ `ControlNetInpaintingAliMamaApply` 把原图+掩码作为控制条件
3. `CLIPTextEncode` 写 prompt,描述要扩展出的内容(如"向右侧扩展出庭院场景")
4. `ModelSamplingAuraFlow`(Qwen 系采样参数) → `KSampler`:`euler/simple`,Lightning 4 步 cfg=1 或标准 20 步 cfg=2.5
5. `VAEDecode` → `ImageCompositeMasked` 将生成区与原始图合成,配合 `GrowMask` + `ImageBlur` 平滑边缘

**8GB 显存加速变体**(RunningHub「加速版」实测):用 `NunchakuQwenImageDiTLoader` 加载 `svdq-int4_r32-qwen-image-lightningv1.1-8steps.safetensors`(int4 量化主模型)+ InstantX ControlNet + Lightning 8 步,8GB 可流畅跑。

**特点**:InstantX ControlNet 对原图保真度极高,扩图时原图内容几乎不变形;中文社区工作流最多、资料最全。

**本机就绪度**:缺 `InstantX_Qwen-Image-ControlNet-Inpainting.safetensors`(约 1.5GB),其余模型齐备。

### 方案 2:Qwen-Image-Edit 2511 扩图(本机零下载首选)

**来源**
- webs\Bilibili:`webs/Bilibili/工作流大全/38fa3aeb-Qwen-扩图.json`(社区)
- 官方模板:`templates/图像/image_qwen_image_edit_2511.json`(编辑主流程);官方文档 `tutorials/image/qwen/qwen-image-edit-2511.mdx`

**模型清单(本机全部就绪 ✅)**
| 文件 | 位置 |
|------|------|
| `qwen_image_edit_2511_fp8mixed.safetensors` | diffusion_models(本机已有) |
| `Qwen-Image-Edit-2511-Lightning-4steps-V1.0-bf16.safetensors` | loras(本机已有;另有 fp32 版在归档) |
| `qwen_2.5_vl_7b_fp8_scaled.safetensors` | text_encoders(本机已有) |
| `qwen_image_vae.safetensors` | vae(本机已有) |

**流程**
1. `LoadImage` → 按需缩放(社区用 `LayerUtility: ImageScaleByAspectRatio V2` / `FluxKontextImageScale`)
2. `TextEncodeQwenImageEditPlus`(Qwen-Edit 专用编码,融合文本语义 + 外观描述)+ `ReferenceLatent`(原图 latent 作参考)
3. `ImagePadForOutpaint` 按四方向扩展画布;`ImageConcatMulti`/`JoinImageWithAlpha` 处理多参考区
4. `CFGNorm` + `ModelSamplingAuraFlow` → `KSampler`:社区实测 **5 步,cfg=1,euler/simple**(配 Lightning)
5. `VAEDecode` → `ImageCompositeMasked` 合成
6. (可选精修)`SEEDVR2_VAE` + `SEEDVR2_DIT` 单步修复,提升边缘与整体清晰度

**特点**:Qwen-Edit 是多模态**编辑**模型(2511 增强版改善图像漂移、角色一致性、多人一致性、集成 LoRA),用自然语言描述扩展内容即可,比 InstantX ControlNet 更自由灵活,可同时扩展多个区域;一致性略逊于 ControlNet 路线,但配 Lightning 4 步非常快。

**本机就绪度**:✅ 全部模型已就位,开箱即用。

### 方案 3:FLUX.1 Fill Dev(官方 inpainting / outpainting 模型)

**来源**
- 官方教程:`docs/ComfyUI-Docs/tutorials/flux/flux-1-fill-dev.mdx`
- 官方模板:`templates/图像/flux_fill_outpaint_example.json`

**模型清单**
| 文件 | 位置 |
|------|------|
| `flux1-fill-dev.safetensors`(或 fp8/GGUF 量化) | diffusion_models |
| `clip_l.safetensors` + `t5xxl_fp16.safetensors` | text_encoders |
| `ae.safetensors`(Lumina VAE) | vae |

**流程**
1. `LoadImage` → `ImagePadForOutpaint`
2. `DualCLIPLoader`(clip_l + t5xxl)→ `CLIPTextEncode` 写扩展 prompt
3. `InpaintModelConditioning`(positive + 负向 `ConditioningZeroOut` + vae + 原图 + mask)→ 生成 inpaint latent
4. `DifferentialDiffusion`(只重绘掩码区)
5. `FluxGuidance` + `KSampler`:官方模板 **20 步,cfg=1,euler/normal,denoise=1**
6. `VAEDecode` → `SaveImage`

**特点**:黑森林实验室官方 fill 模型,扩图/重绘质量高、提示词理解强(仅限英文 prompt),一致性仅次于商用版 FLUX.1 Fill [pro];License 为非商用。

**本机就绪度**:未就绪;需 t5xxl(≈5GB)+ fill dev fp8(≈12GB),8GB 显存紧张(建议 GGUF 量化 + 低分辨率)。

## 六、本机落地建议(8GB VRAM / RTX 4060)

**优先推荐(零下载,立刻可跑)**:
1. **Qwen-Image-Edit 2511 扩图**(方案 2)—— 模型全就绪,配 Lightning 4~5 步;参考 `webs/Bilibili/工作流大全/38fa3aeb-Qwen-扩图.json` 直接改出。
2. 需要更强一致性时,补下 **InstantX ControlNet**(方案 1,≈1.5GB),主模型用本机 `qwen_image_2512_fp8_e4m3fn`(如遇兼容问题再用 InstantX 对应 Qwen-Image 基础版),8GB 建议叠加 int4 量化(`NunchakuQwenImageDiTLoader` + `svdq-int4-r32`)。

**扩图后精修(可选)**:
3. **SeedVR2 3B fp8**(方案 6,≈3.3GB)做最后一步高清修复,8GB 可跑。

**背景 / 风格扩展备选**:
4. **FLUX.2 Klein 9B fp8**(方案 5)本机模型已就绪,可参照 RunningHub「YZ金鱼-Flux2 Klein 多合一」构建 Kontext 扩图工作流。
