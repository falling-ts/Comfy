# 开源生成式世界模型调研（对标 World Labs Marble / Atlas）

- 调研日期：**2026-09-27**
- 起因：0034 走 DA3 多视角重建（8 张弱重叠输入）→ 输出开口墙皮网格，质量远低于 Marble/Atlas；本节回答「**生成式世界模型有没有开源的、能不能达到类似效果、本项目 8GB 显存能否落地**」。
- 结论先行：**有，而且 2026 年集中爆发**；但「从文字/单图凭空造整世界」这一档的开源模型最低显存 ~12GB 起，本机 RTX 4060 **8GB 不是跑不动全部，而是跑不动生成端**；重建端（带 3DGS 输出）有 7–12GB 的可跑方案。
- **最终结论（三路独立检索 + 本机实测后的收敛）**：8GB 上「**可交互 + 显式 3D + 能进 ComfyUI**」三个条件的交集是**空集**（§8.1）；唯一有实测依据、且本机真能跑的完整链路是 §4 的 **L0′**（vggt-low-vram 出位姿 → inpaint 补洞 → gsplat → Spark）；另有一条「开源+消费级本地实时」但**只出视频**的 **Overworld Waypoint-1.5-1B**（Apache-2.0，PyTorch 峰值 6.06GiB）。**本机系统内存仅 15.8GB，也低于 Hunyuan3D 纹理链路要求的 24GB**（§3.2.1）。

## 2. 为什么这些开源项目能接近 Marble（四条共性）

1. **范式相同：生成 + 重建联合，而不是纯重建。**
   HY-World 2.0 = 全景生成（HY-Pano-2.0）→ 轨迹规划（WorldNav）→ 世界扩展（WorldStereo-2.0，用生成模型补出没拍到的区域）→ 世界合成（WorldMirror-2 + 3DGS 优化）。
   ABot-3DWorld 0 = 统一「空间生成基元 SGP（全景图 + 空间点云）」→ 全景视频生成器沿轨迹探索 → 全景视频重建引擎转成干净 3DGS。
   Matrix-3D = 文/图 → 全景图 → 全景视频 → 3DGS。
   **共性是先「生成」把看不见的地方编出来，再「重建」成显式 3D**——这正是我们 0034（DA3 纯几何估计，无生成先验）缺的一半。

2. **原生 3DGS 输出，不是 mesh 硬壳。**
   3DGS 是半透明椭球 + 视角相关颜色，能表达反射、光泽、薄结构；Marble 导出 ~200 万 splats，导出网格只是附带。我们 0034 现在 771,438 三角面、无外观模型 → 观感必然「塑料壳」。
   **好消息：本机 ComfyUI 核心已能读写 spz/ply/ksplat（§3），换掉重建节点即可拿到 splat。**

3. **先验注入（相机/深度/内参）是一等公民。**
   WorldMirror 支持 `prior_cam_path` / `prior_depth_path`，官方把「全部先验」列为精度最高的配置（7-Scenes Acc 0.018 vs 无先验 0.043）。我们的 8 张图目前连「真实机位」都是猜的（H3 无原生相机控制，Atlas 官方评测里相机跟随偏好率仅 25% 给 H3）。

4. **工程不省：递归优化与算力。**
   生成端动辄 17B/80B、5B-12GB 低显存模式、720p 全景视频在 A800 上约 1 小时；Marble 高清网格离线最长 1 小时、限速 4 次/小时。对照 0034 的 **2.66 秒**——这个数字本身就是差距的注脚。

## 4. 针对 0034 的落地路线（按性价比排序）

> 共同前提：**md 数据表结构可以完全不动**——八个 IMAGE 列继续作为「多视角输入」，换的是「表后面那几个节点」。

### L0 —— 当天可做，零成本，质量台阶（推荐先做）
把 `LoadDA3Model → DA3Inference(multiview) → DA3GeometryToMesh → MeshToFile3D` 这一段，换成 **WorldMirror 1.0**：
```
md表 8×IMAGE → ImageBatchMulti → WorldMirror(518px, fp16) → 点云 + 3DGS
                                                     └→ SplatToFile3D(.spz) → 漫游页/Spark 渲染
```
- 收益：输出从「无外观的三角网格」变成**带视角相关外观的 3DGS**，观感直接上一档；点云精度也优于 DA3。
- 风险：8GB 显存需实测——按 8 帧 ≈7GB 的社区数据（在 12GB 卡上测得），需把分辨率降到 448/392、批降到 2–4，并**先卸载 ComfyUI 常驻模型**（实测空闲仅 5.3GB，§3.2.1）；必要时逐帧分批。⚠️ 该节点包**自己标注最低 3060 12GB，8GB 下只验过单帧** ⇒ L0 在 8GB 属于**越界尝试**，不是既定可行。
- 与本机现有能力完全契合（§3.1 的 splat 节点已就位）。

### L0′ —— 8GB 更保险的替代路线（有据可依，但补洞靠生成幻觉）
若 L0 在 8GB 上 OOM，退到「**位姿 + 本地 inpaint 补洞 + gsplat 重训**」这条已被实测证明 8GB 能跑的路：
```
8×IMAGE → vggt-low-vram(出位姿, 8图仅 3.27GB/1.97s) → 导 COLMAP
        → 对空洞视角用本地 Qwen-Image-Edit / FLUX inpaint 出图（掩码 dilate 到 20–30px）
        → gsplat 重训(data_factor 2–4, 480–720p) → SplatToFile3D(.spz) → Spark
```
- 优点：**全链路每一段都在 8GB 内**，且全部本地、无新增大模型依赖（本机已有 Qwen-Edit 2511 fp8mixed + InstantX Inpainting ControlNet）。
- 代价（必须如实告知）：**补出来的墙面是生成幻觉，几何不会真正自洽**，环视到补洞区域会穿帮；一轮 splat 训练 20min–2h，通常要迭代 3–8 轮，累计半天到两天。

### L1 —— 质量再上一台阶（1–2 天，需解决显存）
用 **WorldMirror 2.0（1.2B bf16）**：官方下限 12GB、弹性 50K–500K px。8GB 上必须以最低像素档 + 分批尝试；装 `ComfyUI-HYWM2` 或直接跑 `hyworld2` 仓库（`WorldMirrorPipeline`，支持先验注入：把 0031 那批图已知的机位/内参喂进去能再提精度）。
- 注：8GB 属于官方要求以下，**成功与否要实测**，不能承诺。

### L2 —— 真·生成式（本地跑不动生成端，需算力）
本地可行的只有「**全景生成**」这一小段：HY-World 2.0 的 **HY-Pano-2-Qwen（425M）** 或 Matrix-3D 的 Text2PanoImage（~16GB，仍超）。之后：
- **WorldStereo-2（17B）/ HY-Pano-2（80B）不可本地**；
- 选择：租单卡 4090/A100（参考价 $0.14–0.42/hr）跑 HY-World 2.0 生成流水线；或直接用**官方云服务**（Hunyuan 3D 站点、ABot-World Studio、Marble World API）。

### L3 —— 云端对齐 Marble 质量
Marble World API：`marble-1.1` 一次约 1500 credits = **$1.2**（$1 = 1250 credits，最低充 $5），支持 text / 单图 / 多图 / 360 全景 / 视频 → 返回 SPZ（500k/100k/full_res）+ GLB + 尺度元数据。拿 spz 回本地 → Spark 渲染 → 存档进 md 表，链路与 L0 的后半段完全复用。

## 6. 深挖：稀疏视角 → 完整 3D 到底有没有开源解（2026-09-27 独立检索）

> 检索口径：逐个打开 GitHub API / raw README / 论文页核对，取不到证据的一律标注「未找到」，不编造。

### 6.1 硬结论

**没有任何现成开源模型，能在 RTX 4060 8GB 上、用几张互不重叠的室内照片，直接输出几何闭合的可漫游房间。**

两条原因，缺一不可：
1. **端到端「稀疏视角 + 生成先验」模型全部超显存**（见 6.2 A 组）；
2. **前馈重建类（VGGT / MapAnything / π³ / DA3 / MASt3R / Fast3R）根本不补洞**——它们只把「看见的」量成几何，未观测区域就是空洞，没有任何生成能力。这也正是 0034 现在「开口扇面」的理论上限：换更强的重建模型只会让**看到的部分更准**，不会让房间闭合。

### 8.1 核心结论：「8GB + 可交互 + 显式 3D + ComfyUI」四条件的交集是**空集**

- **8GB + 可交互实时**：基本只有 **Waypoint-1.5-1B**（Apache-2.0，6.06 GiB 实测，建议先试 360P）。⚠️ 该 6.06 GiB **不含 CUDA 上下文等非 PyTorch 开销**，8GB 是紧平衡；且需 BF16 + PyTorch FlexAttention。
- **显式 3D**：Matrix-3D（最低 12GB）/ Roblox Cube（16GB）/ HunyuanWorld 1.0（FP8 20–24GB）/ Lyra（H100 且**权重非商用**）—— 全部越过 8GB；Cube 只能出**单个物体**，Matrix-3D 是**离线数十分钟一条**世界。
- **能导入 ComfyUI 的显式 3D 世界生成**：只有 HunyuanWorld 1.0（20–24GB）。ComfyUI 官方自带的显式 3D 出 GLB 路径是 **Hunyuan3D-2 / TripoSplat / TRELLIS.2**，但那是**单物体生成，不是世界模型、不可漫游**。

### 8.2 两个必须记住的硬件/生态事实

1. **Matrix-Game 系依赖 FlashAttention 3，而 FA3 只在 Hopper+ 可用** ⇒ **RTX 4060（Ada，sm_89）显存够也用不了这条栈**。同理 Waypoint 需要 FlexAttention，具体后端是否覆盖 sm_89 必须实测。
2. **一键脚本/文档里的「最低显存」多来自 GB200/H100/GB300 环境**（Cosmos 3 Nano、Lyra、OmniDreams 分别在 GB200/H100/GB300 验证；社区在 L40S 48GB / DGX Spark 128GB 上的实测值反而是 43.7GB / 27.7GB）。

### 8.3 未取证清单（不要当成结论）

Roblox Cube 代码仓库 LICENSE（raw 抓取失败，仅 HF 卡 openrail）；AMD Micro-World 许可与显存；京东 `jd-opensource/JoyAI-Echo`（仓库存在、README 抓取失败）；`lucidml` 516M 世界模型 **未开源**（HF 组织 0 个公开模型）；「Mirage」/「Lucid Dreams」**未找到对应的开源可玩世界模型证据**；`krmahil/comfyui-hunyuan-world` **两路证据冲突**（一路称 MIT + 3 个 HYWorld 节点，一路称 0★ 无 README）——用前自行核实。
