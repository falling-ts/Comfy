# ComfyUI 启动参数参考(v0.30.0,2026-08-06)

> 来源:直接解析 `ComfyUI/comfy/cli_args.py` 的 argparse,输出 `python -X utf8 -c "from comfy.cli_args import parser; print(parser.format_help())"`。当前版本 ComfyUI `563b98ee`(dev 分支)。
> 当前启动脚本:`start-comfyui.cmd` 使用:`python main.py --enable-manager --disable-pinned-memory --fast-disk`

## 一、网络 / 服务

| 参数 | 说明 |
|---|---|
| `--listen [IP]` | 监听地址,默认 `127.0.0.1`;不带参数则监听所有 IPv4/IPv6(`0.0.0.0,::`),可逗号分隔多 IP |
| `--port PORT` | 监听端口,默认 `8188` |
| `--tls-keyfile` / `--tls-certfile` | 启用 HTTPS,需同时提供 key+cert |
| `--enable-cors-header [ORIGIN]` | 跨域,CORS;默认 `*` |
| `--max-upload-size MB` | 最大上传体积,默认 `100` MB |
| `--auto-launch` / `--disable-auto-launch` | 自动打开浏览器 / 禁止 |
| `--enable-compress-response-body` | 压缩响应体 |
| `--comfy-api-base URL` | ComfyUI API 基础地址(默认 `https://api.comfy.org`) |

## 二、目录 / 路径

| 参数 | 说明 |
|---|---|
| `--base-directory` | 基础目录(models/custom_nodes/input/output/temp/user) |
| `--extra-model-paths-config PATH...` | 加载额外 `extra_model_paths.yaml` |
| `--output-directory` / `--temp-directory` / `--input-directory` | 覆盖基础目录下的对应项 |
| `--user-directory` / `--models-directory` | 用户目录 / 模型目录 |

## 三、设备 / 精度

| 参数 | 说明 |
|---|---|
| `--cuda-device ID...` | 本实例可见的 CUDA 设备列表(其余不可见) |
| `--default-device ID` | 默认设备,其余保持可见 |
| `--cuda-malloc` / `--disable-cuda-malloc` | cudaMallocAsync(torch2.0+ 默认开) |
| `--force-fp32` / `--force-fp16` | 全局强制 fp32 / fp16 |
| `--fp32-unet` / `--fp64-unet` / `--bf16-unet` / `--fp16-unet` | UNet 精度 |
| `--fp8_e4m3fn-unet` / `--fp8_e5m2-unet` / `--fp8_e8m0fnu-unet` | UNet 权重 fp8 存储 |
| `--fp16-vae` / `--fp32-vae` / `--bf16-vae` | VAE 精度(⚠️ `--fp16-vae` 帮助文本明确 **might cause black images**) |
| `--cpu-vae` | VAE 跑 CPU |
| `--fp8_e4m3fn-text-enc` / `--fp8_e5m2-text-enc` / `--fp16-text-enc` / `--fp32-text-enc` / `--bf16-text-enc` | 文本编码器精度 |
| `--fp16-intermediates` | 节点间中间张量用 fp16(实验性) |
| `--force-channels-last` | 推理强制 channels_last |
| `--directml` / `--oneapi-device-selector` | DirectML / oneAPI 设备 |
| `--supports-fp8-compute` | 假装设备支持 fp8 计算 |

## 四、注意力 / 加速(★ H3 相关重点)

| 参数 | 说明 |
|---|---|
| `--use-split-cross-attention` | 分块交叉注意力优化(用 xformers 时忽略) |
| `--use-quad-cross-attention` | 亚二次方交叉注意力 |
| `--use-pytorch-cross-attention` | PyTorch 2.0 交叉注意力 |
| **`--use-sage-attention`** | ⚠️ 全局启用 SageAttention,**替换所有模型 attention**。**本机不加**:曾导致文生图黑图;H3 加速应走工作流节点定向 patch |
| `--use-flash-attention` | 全局启用 FlashAttention(需 `flash-attn` 包) |
| `--disable-xformers` | 禁用 xformers |
| `--force-upcast-attention` / `--dont-upcast-attention` | 强制/禁止注意力 upcast(`--force-upcast-attention` 帮助文本:"please report if it fixes black images") |
| **`--enable-triton-backend`** | 启用 comfy-kitchen Triton 后端(默认禁用;主要供 ROCm/AMD;NVIDIA 用 CUDA 后端即可) |
| `--disable-triton-backend` | 强制禁用 Triton 后端 |

> **关于 SageAttention 的正确姿势**:包 `sageattention 2.2.0+cu130...` 已装(匹配 torch 2.13),但**通过工作流节点**启用(见下方"加速启用方式"),不要用 `--use-sage-attention` 全局替换。

## 五、显存 / VRAM(★ 8GB 卡 H3 相关)

| 参数 | 说明 |
|---|---|
| `--gpu-only` / `--highvram` / `--lowvram` / `--novram` / `--cpu` | 显存策略互斥组(gpu 全驻留 / 模型常驻 / 低显存 / 更低 / 全 CPU) |
| `--reserve-vram GB` | 为 OS/其他软件预留显存(GB)。Windows 默认预留 600MB,16GB+ 卡另 +100MB |
| `--vram-headroom GB` | DynamicVRAM 额外余量,保持这么多显存完全空闲 |
| `--disable-nvml-pressure` | 压力检测改用 CUDA 而非 NVML |
| `--async-offload [N]` | 异步权重卸载流(默认 2,NVIDIA 默认开) |
| `--disable-async-offload` | 关闭异步卸载 |
| `--disable-dynamic-vram` / `--enable-dynamic-vram` | 关/开 DynamicVRAM |
| **`--fast-disk`** | ⚠️ 磁盘动态加载/卸载(NVME 快时更快)。**当前 cmd 已启用**,8GB 卡跑 H3 的关键 |
| `--force-non-blocking` | 强制非阻塞(部分非 N 卡提速,可能引发问题) |
| `--disable-smart-memory` | 激进卸载到普通内存 |

## 六、缓存

| 参数 | 说明 |
|---|---|
| `--cache-ram [GB...]` | RAM 压力缓存(默认模式),第一值激活阈值,第二值 inactive/pin 阈值;默认 active=10% RAM(2-10GB),inactive=100% RAM(≤128GB) |
| `--cache-classic` | 旧式激进缓存 |
| `--cache-lru N` | LRU 缓存 N 个节点结果(更吃 RAM/VRAM) |
| `--cache-none` | 关缓存,每轮全执行 |
| `--high-ram` | 大内存/优先 pagefile 场景提升 |

## 八、H3 加速启用方式(2026-08-06 核查)

| 方式 | 收益 | 怎么用 | 备注 |
|---|---|---|---|
| **comfy-kitchen CUDA 后端**(cu130) | **6-8×** | 无需配置,当前环境已激活(日志 `Found comfy_kitchen backend cuda: disabled=False`) | H3 提速核心,量化权重硬件直算 |
| SageAttention(工作流节点) | ~11-40% | KJNodes `Patch Sage Attention KJ`(`sage_attention=auto`) | ⚠️ 勿用命令行 `--use-sage-attention`(黑图) |
| ~~NB H3 HyperStep~~ | 提速(跳块) | ~~`NB H3 HyperStep`~~ 节点(默认 Turbo 跳36块;Fast 34/Extreme 38) | ⚠️ **已移除**(2026-08-10,兼容性弃用) |
| Spectrum MiniMax H3 | 24-35% transformer 步减少 | `Spectrum Apply MiniMax H3`(默认保守参数) | 近似加速,快速动作小细节可能退化 |
| MiniMaxH3-Cache(EasyCache 增强) | 显著 | 像 EasyCache 一样用 | ⚠️ 会 patch ComfyUI 核心,异常时删插件重启 |
| Sol-Attn triton | 提速(稀疏注意力) | kijai 节点 | ⚠️ 仅 4090/5090 实测,4060 未验证(可能 TMA 路径失败回退) |

> **对文生图(T2I)的影响**:T2I 用 Qwen-Image 等模型(非 H3)。上表所有 H3 加速插件都只 patch H3 模型,**不影响 T2I**。唯一会波及 T2I 的是命令行 `--use-sage-attention` / `--use-flash-attention`(全局替换所有模型 attention)——这正是本机不加的原因。
