# 文件浏览器排序规则

本 vault 的文件浏览器排序由 **Obsidian-Comfy** 插件接管
(`stories/plugins/Obsidian-Comfy`, 自有插件), 不依赖任何第三方排序插件。

## 为什么不能用 Obsidian 原生排序

Obsidian 文件浏览器自带的「按名称 A→Z」**不是**字典序, 而是自然排序 ——
它内部写死 `new Intl.Collator(void 0, {usage:"sort", sensitivity:"base", numeric:!0})`,
`numeric:true` 会把连续数字当**数值**比较, 于是资料表的 5 位编号会被拆散:

| 排序口径 | `00110_万物建模2.1` 的位置 |
|---|---|
| Obsidian 原生(自然排序) | 被当作数值 110, 甩到 `0070_截取声音` 之后 |
| 编号分层(本插件) | 紧跟 `0011_万物建模` 之后、`0012_万物变化` 之前 |

## 排序规则(编号分层)

开头的数字串先按**字符串**比较, 编号相同再比其余部分:

- `0011` 是 `00110` 的前缀 → `0011_万物建模` 排在 `00110_万物建模2.1` 之前
- `00110` 与 `0012` 在第 4 位分出 `1` < `2` → 5 位编号恰好插在它所属的 4 位编号之后

这正是故事库「在编号末尾追加一位数字做中间插入」的编号体系所要求的顺序
(见 `AGENTS.md` 的「资源 ID 规则」)。

⚠️ 注意**纯逐字节排序做不到这一点**: 字符串比较里 `_`(0x5F) 大于数字 `1`(0x31),
所以纯逐字节会把 `00110_万物建模2.1` 排到 `0011_万物建模` **前面**。

## 在哪里配置

Obsidian 设置 → 第三方插件 → Comfy 数据表 → **文件浏览器排序**:

| 选项 | 效果 |
|---|---|
| 编号分层(推荐) | 上文规则, 5 位编号紧跟它所属的 4 位编号 |
| 纯逐字节 | 只按 UTF-16 码位比文件名, 无编号概念 |
| 关闭 | 交还给 Obsidian 原生自然排序 |

改完**立即生效**, 无需重启。

## 历史

本文件此前是第三方插件 **Custom File Explorer sorting**(`SebastianMC/obsidian-custom-sort`)
的 spec 文件, 通过 YAML frontmatter 里的 `sorting-spec` 键配置。

该插件在 Obsidian 1.13.7 上解析失败并自动挂起(ribbon 显示红图标), 原因是
Obsidian 把 YAML 块标量内容连同缩进一起交给插件, 而它对 `target-folder:` 行
要求前导零空格。已于 2026-09-22 卸载, 排序改由本 vault 自有插件接管 ——
逻辑见 `main.js` 的 `compareNumberedName` 与 `setupExplorerSort`。
